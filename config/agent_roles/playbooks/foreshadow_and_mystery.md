# 伏笔、悬疑与知识状态

## core
伏笔必须有稳定 thread ID、表层含义、真实指向、知情角色、计划窗口和正文证据。埋设时应产生当下作用，例如形成误判、改变选择或留下关系压力；不能插入孤立怪句后长期不回响。强化应增加新解释而非重复同一句暗示，兑现必须能回看前文成立。

## creation
调查线要维护线索来源、可靠度、可见对象、替代解释和排除过程。真相不能依靠临时新增规则，侦破也不能来自主角无依据的直觉。读者可以晚于角色知道，但叙事必须明确视角知识边界。

## review
按 thread ID 检查表层功能、知情范围、替代解释、强化增量和兑现窗口，再回读实际正文证据。提前泄漏未来信息或用临时规则完成核心解谜属于严重问题；尚在批准窗口内的未兑现项不能误报。线索含义无法唯一判断时标 insufficient，不替作者补真相。

**诊断分支**
- 埋设无表层功能：让线索先影响一次判断、选择或关系，而不是只登记神秘物件。
- 强化只是重复：增加新证据、新解释或知情范围变化，不重复提醒同一句异常。
- 兑现无法回看：回到既有证据重组推理链；若必须新增救场规则则进入改纲。

## repair
埋设缺功能时让线索先影响一次误判、选择或关系；强化重复时增加新证据或新解释；兑现失败时回到已有证据重组推理链。保护既定真相和知情边界，无法由现有证据成立时请求改纲，不能新增救场规则。

**保护项**：保护既定真相、知情边界、thread ID 和批准窗口，不为制造惊讶篡改旧证据含义。

## facets
悬疑侧重证据公平与替代解释，玄幻侧重规则例外的前置证据，言情侧重秘密如何改变信任，连载文侧重跨章回响窗口，同人侧重 canon 知识与分歧后知识的分离。气氛意象只有被建立为可追问线索时才进入伏笔账本。

## examples
1. 正例：异常账目先导致误判，后续印章证据改变解释；反例：结局突然出现此前不存在的密道。
2. 正例：角色注意到药味并改变座位，当下成立且后来回看有新义；反例：无因果地插入一句“他隐约不安”。
3. 正例：错误线索有可靠来源且能被新证据排除；反例：侦破只靠主角突然想起未写出的常识。

## false_positives
暂未兑现不是缺陷；需要结合批准窗口和本章职责判断。

## calibration
边界例：气氛意象可以不成为伏笔，除非任务或正文把它建立为可追问线索；红鲱鱼不是欺骗读者，只要来源与替代解释公平。兑现延期需有新的因果阻力，不能静默遗忘 thread。
