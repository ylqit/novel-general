# v0.11 动态同人原著资料库

> 状态：v0.11.0 活动能力。本文不授权抓取或重构受版权保护的连续小说、字幕或剧本，也不代表平台会接受、推荐或无法识别机器辅助内容。

## 三级资料归属

```text
当前用户级原著资料库（非 Canon）
-> 具体小说项目的固定资料绑定与全作覆盖计划（workbench）
-> 该小说人工批准的 fanfiction_source_canon_v2（project Canon）
```

用户级资料库使用 `source_library_work_v1`、`source_library_item_v1` 和按内容 hash 固定的 `source_extraction_candidate_v1`。全局事实永远只是候选，不会自动进入任何项目的 Bible、RAG、Graph 或 SQLite。

项目只保存稳定作品/资料项 ID、内容与提取 hash、批准提取、短证据和覆盖状态。项目 Canon 保存本小说采用的连续性、版本选择、人物解释、世界规则修改、蝴蝶效应和跨作品兼容决定。同一全局资料可以被多个项目绑定，但项目 Canon 互不污染。

## 中文动态目录

作品根位于：

```text
50_workbench/同人原著资料/<作品名>/
```

只创建 `作品资料设定.yaml`、`资料绑定.yaml`、`全作覆盖计划.yaml`、覆盖/冲突报告和动态 `资料项/`。小说、动画、人物、事件等媒介或语义目录不会预建；资料项目录名来自人工批准的实际来源，稳定 ID 不受中文目录改名影响。

用户级完整原件默认位于操作系统用户数据目录下的 `原著资料库/`。`LONGFORM_SOURCE_LIBRARY` 只能指定绝对路径。原件、用户资料库、缓存和完整正文不进入项目 Git、出版包、审计包或 Skill。

## 触发边界

- `creation.mode=fanfiction`：开书时自动创建每部作品的最小资料包，并在同人 Canon 和设计前强制覆盖门禁。
- crossover：每部原著独立管理版本、截止点、覆盖率和冲突；全部通过后才允许设计。
- original / inspired_original / adaptation_study：作品名识别只能创建 `external_work_research_request_v1`，人工批准前不联网。
- 非同人项目准备实际使用原著人物、世界或事件：普通研究路径阻断，要求人工切换同人模式。
- 写作中出现未进入项目 Canon 的明确原著引用：创建 `fanfiction_incremental_source_request_v1`，人工批准、搜索/导入、绑定和核销前阻断写作。

模型记忆不能补齐 Canon 缺口，也不能把作品名提及直接升级为网络请求、全局资料或项目 Canon。

## 全作截至截止点覆盖

“全作”是人工选择的权威版本、媒介范围和明确截止点内的全部目录单元，不自动囊括所有改编版本。每个单元必须绑定批准资料项或具备人工确认的不适用理由；必需语义维度缺少证据、原件不可用、hash 漂移或版本冲突未处理都会阻断。

官方梗概只能支持其明确陈述的事件，不能替代人物声音、细节关系或精确规则证据。版本冲突只能人工选择版本、并存隔离或排除。

## Canon、升级与历史影响

`fanfiction_source_canon_v2` 只接受项目当前绑定的资料项、内容 hash、提取 hash 和精确证据 span。未绑定的全局资料、越界 span、重复绑定和连续原文重构都会失败。v1 不迁移、不双读。

全局资料修正只生成 `fanfiction_source_upgrade_proposal_v1` 和影响报告。独立语义审查不能降级由稳定事实 ID 和显式依赖得到的 `must_stale`。未来升级使精确依赖的 Canon/规划/合同 stale；影响已定稿章节时只创建 `revision_branch_v2`，不直接修改绑定或正文。

## 权利与留存

完整原件只接受用户声明合法持有、公版或明确允许的来源。普通网页只保留来源定位、结构化事实、允许的摘要和必要短证据；系统不通过搜索结果拼接完整小说、字幕或剧本。

权利元数据用于留存和来源边界，不构成法律结论。发布仍保持 `literary_evidence_ready=false`，不声明规避 AI 检测、平台必过或人工写作比例。
