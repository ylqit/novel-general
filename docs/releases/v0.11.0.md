# v0.11.0

v0.11.0 publishes the dynamic fanfiction source-library workflow on top of the v0.10 chapter and planning protocol.

## Highlights

- Adds a Chinese user-level original-work library with stable work/item IDs, immutable content hashes, rights-aware retention, and non-canonical extraction candidates.
- Adds per-project Chinese source packs, pinned global bindings, whole-work-to-cutoff coverage plans, dynamic source types, version-conflict decisions, and independent crossover gates.
- Makes `fanfiction_source_canon_v2` the only accepted fanfiction source Canon and rejects v1 without migration or dual reads.
- Prevents ordinary original/adaptation projects from searching on a work-name mention; human approval is required before bounded external research.
- Adds incremental chapter Canon-gap requests, source upgrade proposals, explicit dependency impact, and `revision_branch_v2` routing for finalized chapters.
- Adds Chinese operator mappings and `source-library`, `fanfiction`, and external-work research CLI commands.

## Compatibility

The v0.10 chapter, planning, human-intent, revision, semantic-ledger, event, and reader-promise schemas remain current. Existing fanfiction projects that use `fanfiction_source_canon_v1` must rebuild their source pack and approve a v2 project Canon; no automatic migration is provided.

## Boundaries

Complete source text is retained only for user-claimed authorized, public-domain, or explicitly permitted material. Public web sources keep location, structured facts, bounded excerpts, and permitted summaries; the engine does not assemble protected novels, subtitles, or scripts from search results.

Source-library records remain non-canonical until explicitly bound and approved in a project.
