# longform-novel-engine v0.4.3

`v0.4.3` is the stable protocol, Semantic RAG correctness and production-lifecycle release for Codex App, Codex CLI and Claude Code.

## Highlights

- Reconciles validated repair plans and child repair tasks through complete hash lineage, preventing chapter-close deadlocks.
- Makes repair child creation idempotent and moves ambiguous lineage to `need-human` without weakening closure checks.
- Includes embeddings, vector state, semantic context and SQLite participants in chapter-semantic transactions.
- Uses `evidence_review_v2`, requiring positive prose evidence for checked dimensions and canonical references where the role contract requires them.
- Makes `20_outline/chapter_cards/chNNN.json` the unique chapter contract and binds writing and reviews to `chapter_contract_hash`.
- Rejects removed chapter aliases instead of dual-reading them, including rolling-plan validation and every task renderer.
- Adds transaction v3 `preparing/prepared/applied` crash windows, process-identity locks, explicit SHA/approver recovery and recovery-first production diagnostics.
- Separates full semantic rebuilds from per-source Style Memory, SQLite and vector deltas; chapter apply no longer scans historical prose or rewrites the full embedding export.
- Makes `config/default.engine.yaml` the sole default source and rejects remote vector backend names until real query/upsert drivers exist.
- Rejects unknown and retired configuration fields before merge and exposes value/source/owner details through `validate-config --explain`.
- Uses only `chNNN.md` for draft, final and summary manuscript files, including natural expansion beyond chapter 999.
- Records host, model, engine, workflow and scenario identity for internal evidence readiness.
- Splits RC and public release readiness, and adds Ruff, mypy, branch coverage and repository-local Markdown link validation to CI.
- Deduplicates writing context through an in-memory fact inventory and keeps only the selected chapter direction in canonical delta state.
- Generalizes parent consumption, supersession and lifecycle recovery through `agent-task reconcile`.
- Adds content-addressed candidate blobs, project-setup compaction and stronger artifact verification.
- Separates `protocol_ready`, `production_chain_ready` and `literary_evidence_ready` so structural correctness cannot be presented as literary proof.

## Validation

- Protocol convergence tests cover repair reconciliation, damaged lineage, Semantic RAG rollback, evidence-bound pass, core-reference completeness, generic parent consumption and project-setup compaction.
- Full single-process pytest, Skill validation, resource manifest, readiness and release guards are mandatory local release gates.
- Wheel/sdist audit and a temporary pipx smoke must pass before public release.

## Scope And Limits

- `v0.4.3` does not provide a historical project migration layer.
- Literary evidence remains incomplete and `literary_evidence_ready` remains false.
- No npm or pnpm package, script-side LLM provider, hidden API-key requirement, parallel Agent worker or automatic finalization is introduced.

## Distribution

Install from the immutable `v0.4.3` Git tag using the commands in the repository README.
