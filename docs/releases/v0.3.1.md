# longform-novel-engine v0.3.1

`v0.3.1` 是 Agent 协议与章节状态机热修复版本。它修复语义审稿阶段的无效 manifest 和陈旧正文任务抢占问题。

## 修复内容

- 将语义审稿上下文编译为 3 个输入文件，并严格限制文件数与总字符数。
- 无效 manifest 在注册前失败，不进入任务索引或 lifecycle event。
- submission v2 明确记录当前候选归属、revision、source hash、状态和被替换任务。
- repair/Humanizer/content-expand 替换正文后，旧候选进入 `superseded`。
- `production next` 依据 gate、submission、final 和 closure 推导章节阶段，不再由全局任务优先级跨阶段竞争。
- semantic apply 原子同步候选与章节投影，同时保持 final/RAG/graph/TCS/SQLite 不污染。
- 兼容读取缺少新增字段的 v0.3.0 submission；归属不唯一时停止并要求人工处理。
- 压缩 chapter direction、Humanizer、content-expand 与编辑角色上下文，修复严格注册后暴露的旧生产者契约。

## Skill 兼容

本版本不修改 Codex 或 Claude Code Skill 内容。v0.3.0 与 v0.3.1 的两个 Skill 目录内容哈希保持一致；只需更新 engine，已安装 Skill 的 `status` 不应出现内容漂移。

## 安装

```text
python -m pipx install --force "longform-novel-engine[semantic] @ git+https://github.com/ylqit/novel-general.git@v0.3.1"
longform-engine skills status --tool all
longform-engine doctor --tool all
```

完整安装和升级命令见 [README](https://github.com/ylqit/novel-general/blob/v0.3.1/README.md)。

## 发布与边界

- 失败运行保持 incomplete，不能复用已状态分裂的 runtime。
- 用户明确确认后，`v0.3.1` annotated tag 与 GitHub Release 已公开发布。
- 发布不改变生产边界：不得自动 finalize，也不得绕过 graph/memory/semantic 的显式 apply。
