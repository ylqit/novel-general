# v0.12 语义优先架构

## 1. 架构边界

v0.12 将系统分为三个责任层：

```text
确定性基础设施
  身份、哈希、原始证据位置、权限、状态、事务、版本、stale 与回滚
        ↓
LLM 语义引擎
  搜索规划、资料理解、事实归纳、冲突分析、人物/故事/章节理解与审查
        ↓
人工决定
  资料授权、采用版本、Canon、分歧点、重大节点、正式章节与历史正文变化
```

LLM 可以形成候选、解释和建议，但不能自行扩大网络/文件权限，不能伪造人工决定，也不能直接写 Canon、final、图谱、项目 RAG 或 SQLite。

## 2. 最小硬协议

公共硬协议只描述控制边界：

| 协议 | 责任 |
| --- | --- |
| `artifact_envelope_v1` | 稳定 ID、作用域、输入/内容哈希、状态、创建者、依赖与时间 |
| `source_asset_v1` | 原件身份、真实类型、字节哈希、存储、权利声明和可用性 |
| `evidence_reference_v1` | asset、segment、页/段/区域/cue/时间段/关键帧和短证据哈希 |
| `workflow_record_v1` | 任务种类、状态、授权、输入、输出和诊断 |
| `semantic_document_v1` | 开放中文正文、必要语义主张、证据、范围、不确定性和扩展 |
| `human_decision_v1` | 批准/拒绝/修改、目标哈希、范围、理由和操作者 |
| `agent_task_manifest_v5` | Host Agent 的只读输入、工具、唯一输出、预算和命令 |

资料索引、批次、处理作业和规范化缓存可以有内部确定性记录，但它们只服务存储和重建，不定义人物、事件、关系、能力、服装或跨界规则的封闭本体。

`semantic_document_v1` 的 `document_type` 和 `extensions` 是开放中文值。正文承载完整语义；只有需要进入 Canon、图谱或依赖传播的断言才成为 claim。事实、解释、假设和创作建议必须分层。

## 3. 资料与 Canon 层级

```text
用户级原著证据库（非 Canon）
    ↓ 人工绑定与主张审批
项目采用的原著基线 Canon
    ↓ 显式覆盖
项目同人连续性 / 分歧 / AU / 跨界 Canon
    ↓ 已批准设计与正文
小说自身故事 Canon

仓库角色配置：用户提供的同人案例与写作技法只提炼为 Prompt、质量规则、抽象验收夹具和操作文档，不形成运行时资料域。
```

同一全局资料可以支持多个项目的不同解释；项目之间不共享 Canon。全局资料或处理器更新只形成升级提案。影响未来内容时精确 stale；影响已定稿章节时进入 `revision_branch_v2`。

活动检索域只有 `source_evidence`、`project_canon` 和 `project_story`。`source_evidence` 只服务资料定位、提取和复核，不能直接供正式写作；正式写作只可使用后两者。检索采用需求驱动、作用域过滤、FTS/向量混合召回、重排去重和 Token 预算，不以固定人物/关系/事件条数作为主要边界。v0.12 不提供可搜索的同人作品样本库，也不把用户提供的同人案例、技法或其他同人正文放入项目数据、Canon、RAG 或图谱。

## 4. 动态覆盖

LLM 根据实际路线生成自然语言资料需求。覆盖层级为：

- `identity`：作品、版本、译本和截止点；
- `design_core`：足以批准正式同人路线的人物核心、分歧点和关键规则；
- `volume_scope`：支撑当前卷主要事件和人物状态；
- `chapter_dependency`：当前章节真正要使用的事实；
- `whole_to_cutoff`：人工可选的截至截止点全作覆盖。

默认只有 `design_core` 阻断正式路线、当前章节的 `chapter_dependency` 阻断该章写作。无关远期缺口不阻断当前创作。跨作品项目为每部原著分别计算。

## 5. 多媒体理解

Host Agent 能受控理解整件媒体时优先使用明确文件或范围，CLI 随后验证 asset 哈希、位置和输出边界。文件过大、宿主不支持或结果不可定位时，确定性处理器提供页面、OCR、字幕、ASR、关键帧和时间线证据包。

确定性处理器负责格式识别、位置、规范化和缓存；LLM 负责联合语义理解。任何视觉结论都区分：

```text
直接观察：人物抬起右手，身体后退半步。
解释候选：人物可能在准备发动术式。
禁止自动断言：人物因恐惧而退缩。
```

模型记忆只能产生搜索线索。来源、权利、采用版本、项目 Canon 和历史正文变化始终需要人工决定。

## 6. 小说生产

创作沙盒允许试写、比较路线和测试文风，不更新正式 Canon、图谱、RAG、大纲或承诺账本。人工提升后仍只是待独立复核的候选。

正式生产保持：

```text
项目真值 → 全书方向 → 活动卷 → 重大情节节点审批
→ 最近三章 firm 合同 → 当前章 Story Brief → 人工写作意图
→ 初稿 → 分目标审查/共编 → 人工终稿 → 语义应用
→ 事件与承诺核销 → 章节关闭 → 滚动重规划
```

重大节点需要人工批准；普通对话动作、场景过渡和局部节拍由 LLM 在合同内创作。Story Brief 只给作者可读的开场状态、人物目标、阻力、选择、节点、自由范围、声音/知识边界、读者价值、禁泄露项和结尾新问题，不暴露内部 ID、哈希、原始 RAG 或平台诊断。

人物理解按时期保存价值排序、目标、回避、知识、关系、公共/私下表达、压力模式、代价、语言策略、战斗状态和场景相关外观。服装、表情和环境细节只有在视角可见并服务人物、气氛、关系或伏笔时才进入场景。

### 6.1 中文长篇同人链

同人基线 Canon 获批后不能直接设计路线，正式顺序为：

```text
项目原著基线 Canon
→ 同人故事发动机候选 / 校验 / 人工 apply
→ 同人路线候选
→ 隔离会话独立复核
→ 人工绑定路线与复核 hash 后 apply
→ 活动卷同人投影与重大节点审批
→ 当前章 fanfiction_context_bundle_v2
→ chapter_story_brief_v5 自然中文投影
→ 原著一致性 / 同人创造性双轴审查
```

`同人故事发动机` 必须建立唯一主要初始变量、独立长期目标、可持续阻力、原著人物自主性和原作事件结束后的故事来源。路线使用开放语义主张区分资料证据范围、项目采用截止点、故事切入点和人物知识范围；每项经人工确认的重大分歧都按稳定触发身份产生一份独立、幂等的未来知识可靠性候选，结果只允许“仍可靠、部分可靠、已失效、反向误导”，人工批准并经既有语义 apply 后才可改变正式知识边界。

进入当前卷或重大节点的原著事件必须说明 `保留/提前/延迟/结果改变/换人承担/取消/转化/待决定`。事件命运是规划语义，章节关闭中的 `realized/deferred/cancelled` 是终稿实现证据，两者不重复。原著人物继续拥有独立目标、拒绝权、场外行动和不可被原创主角无因果接管的职责。

跨作品需求由实际 `allowed_elements` 动态生成。每部来源先建立宿主世界适配器，再进入跨界宪法，只有当前卷确实发生的特殊交互才创建例外；不建立全作品两两能力矩阵，不默认不同能量或战力数值等价。

### 6.2 章节同人上下文

内部 `fanfiction_context_bundle_v2` 以 `chapter_contract_v5`、批准 Plot Node、章节语义义务、活动卷和人物表达包为入口：按“全局不可违背承诺 → 显式 claim 引用 → 带字段理由的递归依赖闭包 → 当前来源/人物/事件/卷/篇章结构化范围 → 可选 FTS/向量召回”编译。作者投影使用自然中文；多来源或命名冲突时始终保留来源标签。审阅投影只包含本章选中的精确 claim 和证据闭包，不再投入完整 Canon/故事发动机/路线文档。必需证据预算不足返回包含最大占用项和缩小范围建议的 `prompt_budget_exceeded`，且任何 bundle、任务或状态均不写入。姓名、称号或正文词面不作为主要相关性判断，也不存在“无命中取来源前几条”的正式回退。

作者只看到当前原著时间与场景、批准分歧、人物知识、关系阶段、事件命运、能力/跨界规则、原著人物独立目标、本章原创贡献、禁泄露项、自由范围和章末新状态。claim ID、hash、来源定位、原始 RAG 和检索分数仅留在内部控制面。

### 6.3 审查与中国长篇平台覆盖

`canon_fidelity_reviewer` 分别输出原著一致性与同人创造性。只有违反批准基线/分歧/跨界规则、未来知识越界、原著人物无依据丧失主体性、明确原创贡献义务被违反且机械复演、能力绕过明确成本/反制，或连续复现受保护来源时，才允许形成同人 P1；一般“原创度还不够”只能是 P2 建议。

起点主画像可条件叠加 `cn_longform_fanfiction`，观察开篇原著位置与独有变量、规则检验、第一卷原创主线、人物职责、蝴蝶效应、跨界代价和逐卷重复。它不设固定战斗频率、对白率、短句、升级章数或悬崖结尾。番茄继续只作为 `fanqie_free` P2 非阻断兼容观察。

## 7. 质量目标与边界

修订按因果、人物选择、场景具体性、对白声音、信息释放、节奏重复和文句逐轮进行。项目文风记忆只来自作者明确提供或人工批准的项目文本，不直接模仿在世作者。

系统可以发现模板化、解释过度、人物同声、信息搬运和原著复述等风险，但不声称证明“非 AI”、绕过平台检测、保证签约或保证角色百分之百符合原著。
