# v0.13 国内平台同人长篇架构

v0.13 在 v0.12 的“确定性基础设施 + 开放中文语义文档 + 独立复核 + 人工决定”基础上，正式建模国内平台长篇同人的路线、章节上下文、跨界拓扑、平台质量档和发布权利流程。项目配置继续使用 schema v2；本版本不抓取原著全文，不建立同人样本库，也不把平台启发式或人工风险决定解释为授权或审核保证。

## 1. 生产主链

```text
用户提供并声明权利状态的原著资料
-> 固定 source asset / bundle / normalization / semantic hash
-> 项目独立原著 Canon
-> 同人故事发动机与 route_family
-> 路线候选 / 隔离独立复核 / 人工 apply
-> 章节 fanfiction_context_bundle_v2
-> 作者自然中文 Story Brief
-> 原著一致性与同人创造性双轴审阅
-> 人工终稿 / 语义应用 / 章节关闭
```

创作和发布是两条不同的权限边界。原著权利状态未核验不会阻断故事发动机、规划、写作、审阅、Canon 或人工定稿；只有具体平台发布包导出需要当前有效的目标级人工决定。

## 2. 路线家族与故事承诺

同人故事发动机必须选择一个路线家族：

| `route_family` | 核心责任 |
| --- | --- |
| `oc_si_progression` | 说明插入者的进入方式、知识边界、能力取得、世界内成本、长期目标和无法迅速解决原著矛盾的原因 |
| `canon_character_centered` | 说明原著角色的未满足需求、分歧点、声音和价值观延续、新目标及其他角色自主性 |
| `hybrid` | 说明 OC 与原著角色各自不可替代的目标、职责和关系价值，避免任何一方沦为背景工具 |

三种路线共享八项故事发动机责任：唯一初始变量、独立长期目标、可持续阻力、原著人物自主性、原作事件结束后的故事来源、主角与原著关系、读者识别承诺、原创主线承诺。作品名称和流行模板不能替代这些语义说明。

重要原著事件使用以下因果链：

```text
原著基线
-> 初始变量
-> 保留 / 提前 / 延迟 / 结果改变 / 换人承担 / 取消 / 转化 / 待决定
-> 职责承担者
-> 一阶影响
-> 二阶影响
-> 新问题
```

职责承担者、影响 claim 和适用卷章范围必须引用当前批准的稳定语义声明。事件命运属于规划 Canon；章节关闭时的 `realized | deferred | cancelled` 属于终稿实现证据，两者不能互相代替。

每一项人工确认的重大分歧都有稳定触发身份。系统按触发独立、幂等地生成未来知识重估候选；重复运行不能重复创建。人工批准并应用后，知识范围只能更新为“仍可靠、部分可靠、已失效、反向误导”，并进入后续章节依赖闭包。

## 3. 来源适配器

系统不为具体作品硬编码专用 Prompt 或通用战力表。每个来源通过开放 `semantic_document_v1` 只保存当前路线真正需要的规则、人物、关系、事件和时间点，并绑定证据。

来源适配器至少能够按实际作品表达：

- 条件、领域或规则冲突、能力暴露和组织判断；
- 人体极限、武器、伤病和不可逆死亡；
- 现实身体、游戏身份、退出/死亡条件和系统世界边界；
- 能量、血统、组织责任、情报传播和未来知识贬值；
- 地理、航行时间、海洋限制、阵营和世界级信息传播；
- 身体、灵魂、感知、死亡转化和多世界层；
- 境界、资源、传承、寿命和长时间尺度；
- 能力取得条件、职业、修炼资源、特殊资源独占与反噬。

适配器的目的不是给不同作品排强弱，而是解释能力如何作用、失败、补充、暴露并引发关系和组织后果。

## 4. 章节上下文 v2

`fanfiction_context_bundle_v2` 是唯一接受的同人章节上下文版本；v1 不双读、不迁移，旧包必须重新编译。选择优先级固定为：

```text
全局故事承诺和不可违背规则
-> 章节显式 required claim 引用
-> 带理由的递归依赖闭包
-> 当前来源 / 人物 / 事件 / 卷 / 篇章结构化范围
-> 可选 RAG
```

v2 至少保存：

- `required_claim_ids`：完成章节合同必需的显式声明；
- `dependency_closure`：递归依赖及每条依赖理由；
- `optional_claim_ids`：只用于增强的检索声明；
- `source_partitions`：按来源、人物、事件、卷和篇章划分；
- `author_projection`：不暴露控制面细节的自然中文说明；
- `review_projection`：带来源、稳定 claim ID 和 evidence ID 的精确材料；
- `namespace_collisions`：同名人物、能力、地点和组织冲突；
- `budget_usage`：各分区容量和超额原因。

多来源或命名冲突时，作者投影保留最小必要来源标签；审阅投影始终保留精确命名空间和证据闭包。审阅器不再读取完整 Canon、故事发动机和路线文档。必需声明超预算时，在任何 bundle、任务或状态写入前返回可操作的 `prompt_budget_exceeded`，列出最大占用声明和建议缩小范围；不得静默截断。

来源版本、项目 Canon、故事发动机、路线、章节合同或所依赖声明变化后，bundle、Story Brief basis 和所有绑定旧 hash 的审阅结果必须 stale。

## 5. 跨界拓扑

跨界路线只接受三种显式拓扑：

| `topology` | 约束 |
| --- | --- |
| `fixed_host` | 必须提供唯一 `default_host_source_id` |
| `fusion_world` | 默认宿主必须为空，并提供世界规则优先级、共同历史和组织/地理重构声明 |
| `sequential_worlds` | 每卷声明唯一当前宿主、进入/退出条件、跨卷保留项、债务和总主线进度 |

每个 transfer 声明来源和实际 `payload_kinds`：`character`、`body_or_soul`、`ability`、`item_or_contract`、`knowledge`、`organization` 或 `world_rule`。需求编译器只针对实际载荷生成相互作用问题，不预建 N×N 世界组合。

跨界验证顺序固定为：

```text
来源适配器
-> 项目跨界宪法
-> 当前卷例外
```

验证内容包括能量转换和补充、作用对象、激活条件、成本、冷却、损伤、失败方式、当地反制、感知和信息传播、身份与组织响应、死亡/复活/返回/召唤/契约，以及不可逆后果。顺序诸天至少保留一项人物关系、身体状态、资源债务、敌对关系、知识失效或总目标进度，禁止卷末完全重置。

## 6. 国内平台质量档与发布权利

共享 `cn_longform_fanfiction` 合同之上有两个目标层：

- `qidian_male`：主验收档，强调长主线、卷级增长、持续阻力、原著人物价值和原作事件结束后的后续故事来源；
- `fanqie_free`：同人兼容档，强调移动阅读清晰度、较快兑现、反填充、反粗制批量生成和章节可读性。

两者都不编造固定字数、更新量、签约规则、推荐算法、对白率或悬崖结尾配额。平台政策注册表把分类、投稿、签约、特定激励、内容治理、权利风险、披露要求和未知项分开保存，并记录官方来源、验证日期和下次复核日期。

`platform_publication_preflight_v2` 显示目标平台观察、`rights_decision_status`、`decision_stale` 和 `export_blocking`，但不预测审核结果。`fanfiction_publication_rights_decision_v1` 按目标保存 `proceed | hold`，并绑定：

- 当前有效项目配置 hash；
- 当前批准的来源 Canon hash；
- 每个来源的权利声明 hash；
- 目标平台政策快照 hash；
- 决定人、时间和非空说明。

当权利状态未核验或存在商业意图时，`proceed` 必须提供风险说明。决定不保存原著正文、完整 Prompt 或小说正文。决定缺失、为 `hold`、任一绑定漂移或政策复核过期时，只阻断对应 `publication export --target ...`；原创项目和普通创作链不触发该门禁。人工决定只表示风险知情和流程责任，不是法律意见、原著授权或平台接受保证。

## 7. 文学证据

工程测试、作者接受和发布成功不能把 `literary_evidence_ready` 改为 true。同人文学证据需要一条 OC/SI 20 章路线和一条原著角色中心 20 章路线、当前 hash-only 自动门禁报告、每条路线三名未参与生成的独立人类盲审、固定中位数阈值，以及对全部实质评审分歧的人工处理记录。系统不能覆盖分数或选择更有利意见。

仓库不提交试写正文、原著资料或完整 Prompt 日志。当前没有满足要求的真实材料，因此 `literary_evidence_ready=false`。
