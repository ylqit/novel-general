# Longform Novel Iron Laws

These rules apply to Codex, ClaudeCode, and any other Agent-Skill user of `longform-novel-engine`.

1. Agent-Skill mode is the default production path. `writing.mode = agent_skill` means Codex or ClaudeCode writes prose, and the CLI controls context, gates, RAG, graph, SQLite, rollback, and persistence.
2. Skill mode does not require an extra LLM API key. Do not ask the user for provider API keys; the public runtime exposes no script-internal provider mode.
3. Files are the source of truth. SQLite is only a rebuildable derived index.
4. Agents must not free-write official chapters directly in chat when a project exists. Always use the command workflow.
5. Agents may write chapter prose only under `50_workbench/agent_drafts/`.
6. Agents must not directly write or edit `40_manuscript/final/`, `60_rag/`, `30_state/story_graph.json`, or `70_runtime/db/`.
7. `draft submit` is the only legal path from Agent draft to managed draft state.
8. `chapter finalize` is the only legal path from managed draft to final manuscript.
9. A failed gate blocks the next chapter. If `gate_result.json` has `passed=false`, run repair, waiver, branch, or rollback workflow before continuing.
10. A previous chapter that is not final blocks the next `continue-write`.
11. Failed drafts do not enter RAG, story graph, final manuscript, or final SQLite state.
12. Unpromoted `50_workbench/research_inbox/` material must not enter canon, RAG, story graph, or writing tasks.
13. Only `research promote` can move reviewed material into `10_bible/research_canon.jsonl`.
14. Rollback must preserve later material as detached drafts and mark chapter cards, writing tasks, RAG, graph, summaries, and SQLite status stale.
15. Official chapter prose must not contain TODO notes, writing instructions, character labels, AI self-reference, or prompt residue.
16. `creation.mode = fanfiction` is a first-class production mode. Character names, relationships, worlds, abilities, timelines, continuations, prequels, AU, divergences, and crossovers are valid only after user-library registration, project hash binding, dynamic `identity/design_core` coverage and project Canon approval. `volume_scope/chapter_dependency` are evaluated when their scope becomes active; `whole_to_cutoff` is a hard gate only after a human explicitly selects it.
17. Fanfiction rights status and commercial intent are user-claimed advisory metadata. They must produce warnings and provenance, but must not block task creation, validation, finalization, or export.
18. Allowing fanfiction does not allow continuous source-prose reproduction. Complete originals stay only in the user-level library when rights permit; project Canon stores paraphrased facts plus pinned item/content/extraction hashes and bounded exact evidence. Chapters must not copy, split across fields, or reconstruct source passages.
19. Fanfiction Agents read only manifest-declared approved project-pack artifacts and canon digests. They must not scan the user library, an undeclared source work, another novel project, or a research inbox for extra canon. Non-fanfiction work mentions create pending research requests and never trigger network access automatically.
20. Every prose revision must preserve the chapter contract, knowledge boundaries, ability costs, relationship stage and protected outcomes. Empty prose, prompt residue, format damage and large exact repetition may block deterministically; word lists, sentence length, dialogue ratio, sensory density, slow chapters and hook strength may not independently produce P1. No rewrite-ratio or detector score is used.
21. A planned `reader_gain` is not an observed payoff. When `production next` requires `reader_payoff_review`, the Agent must cite the current draft and pass `quality payoff-validate` before explicit finalization.
22. Unfinalized payoff reviews remain in `50_workbench/quality_reviews/`. Only `chapter finalize` may write `reader_reward_entry_v2` and `30_state/quality/structure_history.jsonl`.
23. Structure observation must not impose a universal cliffhanger, battle, reversal, upgrade, short-sentence, or dialogue template. One repeated dimension is a warning; only combined structure, language, and payoff repetition may block.
24. `book_ideation` asks one question per round. Agents may offer options, but only a user's explicit selection or provided answer may enter `10_bible/creative_decisions.json`.
25. Every unapplied chapter requires `chapter_direction`: the Agent offers two or three causally distinct options with costs, and only the user's explicit selection may unlock the chapter card and writing task. An already applied direction remains resumable.
26. The effective quality contract is compiled from resource profiles and explicit project state. Agents must not treat it as a fixed sentence, dialogue, pace, or ending template.
27. Approved style baselines never auto-expand. Only an explicit CLI command with a named human approver may add a finalized chapter's prose-free craft observation.
28. Editorial roles are risk-selected and context-isolated. A role reads only its manifest inputs and must not read peer results before submitting `editorial_role_review_v2`.
29. Editorial aggregate must preserve evidence-backed disagreement. A minority P0/P1 cannot be removed by majority vote and requires an explicit human decision.
30. Editorial patterns are derived diagnostics under `50_workbench/editorial_patterns/`, never reader behavior, a canonical fact source, or author context. Only structured `role_id + finding_code` review findings may create them.
31. Current P0/P1 findings remain in the immutable review bundle and block repair/finalization there. The pattern registry never gates by itself: P1 closes only with editor or human evidence; P2 may expire after three complete chapters; corruption is a doctor warning repaired only by explicit rebuild.
32. Final manuscript is the prose evidence source; a semantic summary routes retrieval but cannot prove a relationship, memory, foreshadow, timeline, or world-state change by itself.
33. Each newly finalized chapter must use one Agent-authored `canonical_delta_v1`; only the CLI may normalize it into the internal semantic ledger. The default production path must not create separate graph, chapter-memory, and character-memory Agent extraction tasks for the same final.
34. `chapter semantic-apply` is the only default path that materializes the chapter semantic ledger into graph, character current views, foreshadow state, TCS, RAG, and SQLite. It must validate exact source spans and apply transactionally.
35. `chapter close` is required before continuing to the next chapter. It preserves final, semantic ledgers, planning ledgers, and current materialized state while allowing older workbench artifacts to move into verified chapter audit archives.
36. SQLite and vector indexes are rebuildable derivatives. They must never override final text or the evidence-bound semantic ledger.
37. `chapter_contract_v5` is the only formal chapter contract. It comes from the firm layer and binds readable topology, observable change, reader value, semantic obligations, approved plot nodes and explicit reader-promise actions; old cards, aliases, dual reads and automatic migration must fail validation.
37a. `planning_generation_task_v1` is the production planning renderer contract. In fanfiction mode every active-volume, semantic-obligation, Plot Node and chapter-channel claim ref must resolve to one current approved claim and satisfy all declared scope dimensions before any planning transaction; in original mode the formal claim lists remain present and empty.
38. Interrupted storage must begin with `recovery status`. Recovery requires the exact reported SHA and a named approver; Agents must never delete project locks, transaction reports, or snapshots directly.
39. Per-chapter semantic apply uses only the current chapter and changed memory sources. Full embedding export/rebuild is explicit and must not be disguised as an incremental chapter update.
40. The author reads only `chapter_story_brief_v5`; it includes readable topology, story obligations, approved nodes, character choices, reader value, bounded necessary character voice and relevant facts. Fact IDs, source hashes, promise IDs, internal node IDs, pattern codes, planning ledgers, raw RAG packets, Graph/SQLite vocabulary and evidence provenance remain in internal planning/editor/archivist lanes.
41. `scene_prose_editor` and `anti_template_editor` independently review every chapter. A template P1 requires at least two exact spans, one repeated narrative function, reader harm and protected content. Planning, reader-experience, character and canon roles remain additive.
42. Finalization requires a current `human_author_revision_v4` final lock plus `human_story_review_v7` accept bound to candidate, chapter contract, human intent, Story Brief basis, reader-promise ledger, approved Plot Node table, semantic-obligation ledger, immutable review bundle and human revision. Humans supply exact key-turn, character-choice/emotion and reader-gain evidence; every finding needs an explicit disposition.
43. `reader_promise_ledger_v2` describes explicitly approved author-side expectation management, not clicks, retention, comments or any other observed reader behavior. It creates no hidden default promises; every non-defer chapter action requires an exact final span, the current semantic-ledger hash and human confirmation before close.
44. The rolling planning window is a human-approved constraint, not a prose template or world fact. `production next` requires an active volume, at least three firm chapters and current planning basis hashes; changed basis hashes make downstream contracts, nodes, Story Briefs and tasks stale.
45. Literary-quality claims require blind-review v4 evidence from three different genres covering both market openings and the fifteen-chapter serial arc, with three independent human judges per group, absolute quality thresholds, required v0.8 improvements and no confirmed long-term failure. Missing or tampered evidence keeps `literary_evidence_ready=false`.
46. Chapter-direction Markdown must offer two or three stable option IDs. `chapter_direction_selection_v1` binds the document hash, selected option, human adjustments and carrier-repetition reason; approval and semantic compilation consume both artifacts.
47. `human_review_consult` is non-canonical. In `coedit`, a recorded human option selection may create one complete workbench rewrite task; in `human_final`, consultation is always read-only. Neither phase may approve/finalize a chapter.
48. The local review desk listens only on loopback and cannot create a canonical write path. A consultation suggestion becomes a review annotation only through an explicit human action.
49. Human prose edits are complete workbench candidates submitted as `agent=human`; ordinary revision does not consume repair budget, while a candidate bound to a validated repair plan consumes that round. Both rerun the complete gate and independent-review barrier.
50. A human revision records at least two substantive impact dimensions, including scene causality or character voice/emotion, with exact before/after spans, intent refs, reader effects and protections. Whitespace-, format- or punctuation-only changes fail. Any later Agent/naturalness/repair prose transform invalidates the final lock.
51. `chapter_story_brief_basis_v3` binds every projection that can change the author work order, including the current contract, Plot Node approval, semantic obligations, rolling window and `human_chapter_intent_v2`. A writing task may be reused only when task status, contract, intent, basis, Markdown bytes and the active manifest are all current.
52. `human_chapter_intent_v2` starts blank and must be completed by a human after Plot Node approval. No frontend, Agent or CLI may prefill its creative answers; stale node approval or contract hashes block writing.
53. `chapter_coedit_session_v2` stores bounded decisions, spans, option IDs, intent and candidate hashes rather than full prompts or unrelated chat. Every applied suggestion creates a complete workbench candidate and cannot bypass repair budget.
54. Every approved plot event reaches a human-confirmed `realized`, `deferred` or `cancelled` state before chapter close. Realized events cite exact final spans and the current final/semantic hashes.
55. Canon changes use stable fact IDs and explicit dependency references. Deterministic `must_stale` impact cannot be downgraded by semantic review; changes that affect finalized chapters enter `revision_branch_v2` from the earliest affected chapter through the current head.
56. Reader feedback is non-canonical. A human decision may convert a hypothesis only into a planning proposal or canon-change proposal; feedback never directly changes prose, promises, canonical facts or platform policy.
57. An approved fanfiction source Canon does not unlock route design by itself. A human-approved `同人故事发动机` must first establish one primary initial variable, an independent long-term goal, sustainable resistance, canon-character agency and a post-canon source of story; the route then requires a separate isolated review bound to the exact route, engine and Canon hashes.
58. Source evidence range, project Canon cutoff, story entry point and each character's knowledge range are different truths. Each realized major divergence opens its own idempotent future-knowledge reassessment; an LLM may propose only `仍可靠/部分可靠/已失效/反向误导`, but only an exact provenance-bound, human-approved semantic apply may update downstream knowledge boundaries. Applicability and evidence retention are separate: delayed results retain proof before they apply, expired results leave chapter context, and every approved chain is sealed into an immutable provenance archive before normal compaction may release its live evidence.
59. Every canon event used by a current or future major node has an explicit fate claim: `保留/提前/延迟/结果改变/换人承担/取消/转化/待决定`. Changing it stales only explicit future dependencies; finalized impact enters `revision_branch_v2`. Chapter event realization remains the separate final-text evidence ledger.
60. Crossover requirements are generated from the actually allowed elements. Each participating source uses a host-world adapter, then the project-wide crossover constitution, then only current-volume exceptions. Do not build a full pairwise power matrix or treat energy systems as equal without an approved semantic rule.
61. `fanfiction_context_bundle_v2` is the only accepted internal rebuildable projection. It selects narrow global promises/invariants, explicit chapter refs, reasoned recursive dependencies, structured current scope, then optional RAG; preserves source namespaces, collisions, exact evidence closure and partition budgets; and fails before any write with actionable `prompt_budget_exceeded` rather than truncating hard evidence. The author sees natural Chinese (with source labels for multi-source/collisions); fidelity reviewers receive only its exact review projection, never whole Canon/story/route documents.
